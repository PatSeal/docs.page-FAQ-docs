---
title: Glossary
description: Plain-language definitions for common web-development terms.
---

## A–C

**Abstraction**

A small public contract that hides implementation detail callers do not need.

**API (Application Programming Interface)**

A defined way for software systems to communicate. A web API commonly uses HTTP requests and JSON responses.

**Authentication**

The process of establishing an identity, such as verifying a password and creating a session.

**Authorization**

The decision about whether an identity may perform a specific action on a specific resource.

**Backend**

Code running in a controlled server environment. It applies trusted rules, accesses data, and integrates private services.

**Browser**

A client application that requests web resources, interprets HTML and CSS, executes JavaScript, and presents the result.

**Cache**

Stored reusable data that avoids repeating slower work. Every cache needs freshness, invalidation, and privacy rules.

**CDN (Content Delivery Network)**

A distributed network that serves cacheable resources from locations closer to users.

**CI/CD**

Automation for integrating, testing, packaging, and delivering changes in a repeatable way.

**Client**

Software that sends a request to a server. A browser, mobile app, or another server can be a client.

**Class**

A JavaScript definition for constructing objects with related state and methods.

**Component**

A focused, reusable interface unit with defined inputs, behavior, and output.

**Composition**

Building an object's behavior by injecting and delegating to collaborating objects. It represents a “has-a” relationship.

**Cookie**

A small value a server asks a browser to store and send with matching future requests. Cookies are often used for sessions and preferences.

**CORS (Cross-Origin Resource Sharing)**

HTTP response rules that tell a browser which other origins may read a resource.

**CSS**

The language used to control the presentation and layout of HTML.

## D–H

**Database**

A system that stores, queries, updates, protects, and recovers durable data.

**DNS (Domain Name System)**

The system that resolves human-readable hostnames to network information.

**DOM (Document Object Model)**

The browser's object representation of an HTML document, available to JavaScript.

**Dependency injection**

Supplying an object's collaborators from outside, commonly through its constructor, instead of creating hidden concrete dependencies inside it.

**Encapsulation**

Protecting state and invariants behind an object's public methods.

**Entity**

A domain object defined by a stable identity and responsible for protecting related state and rules.

**Endpoint**

A specific API method and route, such as `GET /api/tasks`.

**Environment variable**

A named configuration value supplied outside source code. Server secrets can be supplied this way through a protected platform; frontend variables are not secret once built into browser code.

**Frontend**

The part of a web application that runs in the browser and manages presentation and interaction.

**Framework**

A collection of conventions and code that supplies the structure in which an application is built.

**Git**

A distributed version-control system that records project snapshots and supports branches and collaboration.

**HTML**

The markup language that describes the structure and meaning of web content.

**HTTP**

The application protocol used for requests and responses on the web.

**HTTPS**

HTTP sent through an authenticated, encrypted TLS connection.

## I–P

**Idempotent**

An operation whose repeated identical requests have the same intended effect as one request.

**Index (database)**

A data structure that speeds selected lookups and ordering at the cost of storage and write work.

**Inheritance**

A relationship in which a subtype extends a base type and must remain safely substitutable for it.

**JavaScript**

A programming language used for browser behavior and in server runtimes such as Node.js.

**JSON (JavaScript Object Notation)**

A text format for structured values, commonly used in API bodies.

**Migration**

A versioned change that moves a database schema or data from one known state to another.

**Middleware**

Code in a server request pipeline that handles a shared concern before or after a route handler.

**Node.js**

A runtime that executes JavaScript outside the browser, commonly for servers and development tools.

**Object**

A value with identity, state, and behavior. In OOP, objects collaborate through public contracts.

**OOP (Object-Oriented Programming)**

A design approach that organizes application behavior around encapsulated objects and their collaborations.

**Origin**

The combination of protocol, hostname, and port. Browsers use it as an important security boundary.

**Package**

Reusable code distributed for installation as a dependency.

**Parameterization**

Sending untrusted values separately from query or command syntax so they remain data instead of executable structure.

**Promise**

A JavaScript object representing the eventual success or failure of an asynchronous operation.

**Polymorphism**

The ability to replace one object with another that honors the same behavioral contract.

## Q–Z

**Query**

A request to read or change data, often written in SQL for a relational database.

**Responsive design**

An approach that lets an interface adapt to available space, content, input method, and user preferences.

**REST**

An architectural style centered on resources, representations, and standard HTTP semantics. Many JSON APIs use some REST ideas without implementing every constraint.

**Repository**

An application-owned abstraction that loads and saves domain objects while hiding persistence details.

**Route**

A method and path pattern mapped to application behavior.

**Runtime**

The environment that executes code, such as a browser or Node.js process.

**Schema**

An explicit description of data structure, fields, types, relationships, and constraints.

**Server**

Software that listens for requests and returns responses. The word can also refer to the computer or managed service running that software.

**Session**

Server-recognized state that connects several requests to an authenticated user or interaction.

**SQL**

A language for defining and working with relational data.

**SOLID**

Five design principles covering focused responsibility, safe extension, subtype substitutability, small interfaces, and dependency inversion.

**State**

Data that can change while an application runs and influences its behavior or displayed interface.

**TLS (Transport Layer Security)**

The protocol that encrypts and authenticates HTTPS connections.

**Transaction**

A group of database operations that commit together or roll back together.

**URL (Uniform Resource Locator)**

An address identifying how and where to request a resource.

**Validation**

Checking whether input matches required structure, types, formats, limits, and business rules.

**Value object**

An object defined by its validated value rather than a separate identity, such as `TaskTitle` or `EmailAddress`.

**Web server**

Software that accepts HTTP requests and returns HTTP responses.

**XSS (Cross-Site Scripting)**

A vulnerability in which attacker-controlled content executes as script in another user's browser.
